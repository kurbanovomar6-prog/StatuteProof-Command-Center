# Current-State QA — After Auth D2 and Design 4A

## 1. Verdict

Current state is strong for a controlled founding-pilot MVP: real account auth, profile persistence, Telegram pairing, user-triggered sample delivery, and approved-alert dry-run preview are present and separated from global/admin Telegram behavior.

The biggest remaining risk before external pilot is endpoint hardening: global Telegram settings endpoints are still public, and `/api/source-test` is public. These should be protected or otherwise constrained in Auth E1 before exposing the API beyond controlled local/internal use.

No automatic production alert delivery, scheduled delivery, bulk delivery, or weekly delivery to users was found.

## 11. Endpoint classification

Public safe:

- `GET /api/health`
- `GET /api/`
- `POST /api/contact` — intended public contact endpoint, but should have rate limiting/captcha/queue hardening before external traffic
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/logout` — safe to call unauthenticated; deletes session if present

Auth-required user endpoints:

- `GET /api/auth/me`
- `GET /api/profile`
- `PUT /api/profile`
- `POST /api/telegram/pair/generate`
- `GET /api/telegram/pair/status`
- `POST /api/telegram/pair/unlink`
- `POST /api/telegram/test`
- `POST /api/delivery/test-brief`
- `GET /api/delivery/logs`
- `GET /api/delivery/preview`
- `POST /api/delivery/send-preview-alert`

Global/admin endpoints:

- `GET /api/settings/telegram`
- `POST /api/settings/telegram`
- `POST /api/settings/telegram/test`

Risky and should be protected in Auth E1:

- `GET /api/settings/telegram`: currently public, exposes public-safe global settings but still admin surface.
- `POST /api/settings/telegram`: currently public, can save global Telegram settings, including chat ID and optional bot token.
- `POST /api/settings/telegram/test`: currently public and can trigger a global Telegram test send if configured.
- `POST /api/source-test`: currently public. It has SSRF validation, but it can trigger outbound source compatibility checks and should be auth-required/rate-limited before external exposure.
- `POST /api/contact`: expected public, but should be rate-limited and abuse-protected.

## 12. Risks before external pilot

Highest priority:

- Protect global Telegram settings/test endpoints behind admin auth or remove them from public API surface.
- Add CSRF protection or another cookie-safe mutation strategy for authenticated endpoints.
- Add rate limiting for auth, contact, source-test and delivery endpoints.
- Add production cookie `Secure` behavior when HTTPS is guaranteed.
- Clarify Integrations copy now that D2 manual preview delivery exists in Alerts.

Medium priority:

- Add automated tests for user isolation across profile, delivery logs, Telegram pairing and alert preview.
- Add explicit admin/operator workflow before any D3 scheduled or production delivery.
- Consider cleaning compile-generated `__pycache__` from grep surfaces if it interferes with QA scripts, though it is not currently tracked.
